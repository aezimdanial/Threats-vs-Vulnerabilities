# Threats vs Vulnerabilities

| Aspect | Threat | Vulnerability |
|---|---|---|
| **Definition** | Any potential event, action or actor that could cause harm to a system, data or organisation. | A weakness or flaw in a system, process or control that can be exploited. |
| **Nature** | External or internal danger — something that *may happen*. | Internal weakness — something that *already exists*. |
| **Origin** | People (hackers, insiders), nature (floods, fire) or accidents. | Poor design, bugs, misconfiguration or human error. |
| **Intention** | Can be intentional (attack) or unintentional (disaster, mistake). | Not intentional — it is a condition, not an action. |
| **Control** | Cannot be fully eliminated; can only be monitored and blocked. | Can be found, patched, fixed or reduced. |
| **Detection** | Threat intelligence, IDS/IPS, SIEM, monitoring. | Vulnerability scanning, penetration testing, audits. |
| **Kali Linux tools** | Wireshark, Snort (observe threat activity). | Nmap, Nikto, OpenVAS, sqlmap (find weaknesses). |
| **Analogy** | A burglar walking around the neighbourhood. | An unlocked door or broken window in your house. |
| **Relationship** | A threat needs a vulnerability to succeed. | A vulnerability is only dangerous if a threat can exploit it. |
